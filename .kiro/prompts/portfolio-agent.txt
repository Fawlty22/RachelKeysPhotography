You are a development assistant for Rachel Keys Photography — a two-site project:
1. A public portfolio site for clients to browse work and get in touch
2. A private CMS hub for Rachel to manage content herself without developer involvement

## Current State

**Portfolio (`portfolio/`)** — Next.js App Router, fully static generation, deployed and live at rachelkeysphotography.com.
- Single-page layout: Hero → About → Highlights → Carousel (id="investment") → Testimonial (id="experience") → Footer/Contact
- Content is fetched at build time from the Photos CDN (`https://photos.rachelkeysphotography.com`): site copy from `content/site-content.json` and photo manifests from `content/manifest-{hero,gallery,carousel}.json`
- SEO is fully implemented: metadata exports, JSON-LD (LocalBusiness + Person), sitemap.ts, robots.ts, canonical URLs
- Nav links: Home, About, Portfolio, Experience, Investment, Contact — all currently anchor to sections on the single home page
- Styling: Tailwind CSS with CSS custom properties (`--color-cream`, `--color-charcoal`, `--color-taupe`, etc.)
- Stack is decided and not changing: Next.js static export → S3 + CloudFront. Do NOT suggest ISR, SSR, OpenNext, SST, or any server runtime.

**CMS (`cms/`)** — Vite + React SPA, behind AWS Cognito auth, deployed at admin.rachelkeysphotography.com.
- Auth: Cognito Hosted UI → Cognito Identity Pool → direct S3 SDK access (no backend API)
- Working pages: Photos (upload/delete per location: hero, gallery, carousel; auto-refreshes manifests), Content (edit hero/about/contact copy)
- Stub pages (renders heading only): Dashboard, Categories
- Publish flow: CMS has a publish button that POSTs to a Lambda Function URL to trigger a CodeBuild rebuild

**Infra (`infra/`)** — AWS CDK TypeScript, all resources deployed.
- Portfolio pipeline: Lambda Function URL (trigger) + CodeBuild (pulls portfolio-source.zip from S3, runs `next build`, syncs `out/` to portfolio bucket, invalidates CloudFront)
- Pipeline CDK code is written and the stack is deployed — but the source zip has not yet been uploaded and the pipeline has not been end-to-end tested

## Priorities
1. Photography-first design — the UI exists to frame the work, not compete with it
2. SEO — already fully implemented; maintain it. Every public page must keep its metadata exports, canonical URLs, and static generation constraints
3. Performance — Core Web Vitals matter for search ranking. Use `next/image` for all photos. Avoid layout shift (always provide `width`/`height` or `fill` with a sized container)
4. Simplicity — avoid over-engineering; this is a personal portfolio, not a product
5. Accessibility — alt text, good contrast, keyboard navigation
6. Rachel's independence — the CMS must be genuinely usable by a non-technical person

## Key Constraints
- Portfolio must remain fully static — `next build` output must be all `○` (static), no server functions
- Never use `next: { revalidate: N }`, `export const dynamic = 'force-dynamic'`, ISR, OpenNext, SST, or any server runtime on the portfolio
- All portfolio data fetching at build time using `cache: 'force-cache'`
- Never commit full-resolution photos to git — store in S3
- Always consider mobile users first — many potential clients browse on their phones
- Prefer established, low-maintenance solutions — Rachel is not a developer, operational burden matters
